# Product Return-Rate Pattern Analysis

End-to-end pipeline: simulated E-commerce transactions -> Kafka streaming ->
HDFS storage -> MapReduce aggregation -> return-rate calculation & flagging.

Everything runs in Docker (Kafka, Hadoop HDFS+YARN, and a Python `app`
container), so nothing needs to be installed on Windows itself besides
Docker Desktop, which is already present on this machine.

## Project layout

```
BDA/
  docker-compose.yml        # Kafka, Zookeeper, Hadoop (HDFS+YARN), app container
  Dockerfile.app             # python container for our scripts
  Dockerfile.nodemanager     # adds python3 to the YARN NodeManager (needed to run mapper/reducer)
  hadoop.env                 # Hadoop cluster configuration
  requirements.txt           # kafka-python, pandas, hdfs, faker, numpy

  data/
    generate_dataset.py      # Step 1: simulate the E-commerce transactions dataset
    explore_dataset.py       # Step 1: missing-data report + cleaning
    raw/                     # transactions.csv, transactions_clean.csv (generated)
    streamed/                # transactions_stream.jsonl (generated by the consumer)
    output/                  # MapReduce output + final CSV report (generated)

  kafka/
    producer.py               # Step 2: streams transaction/return events into Kafka
    consumer.py               # Step 2: consumes + verifies + buffers to disk

  hdfs/
    store_to_hdfs.py          # Step 3: uploads buffered events into HDFS, verifies

  mapreduce/
    mapper.py                 # Step 4
    reducer.py                # Step 4
    run_job.sh                 # Step 4: submits the Hadoop Streaming job

  analysis/
    return_rate_analysis.py   # Step 5: return-rate calc, trend detection, flagging
```

## One-time setup

```powershell
cd C:\Users\User\OneDrive\Desktop\BDA
docker compose up -d --build
```

This pulls/builds: Zookeeper, Kafka, 5 Hadoop services (namenode, datanode,
resourcemanager, nodemanager, historyserver), and the `app` python
container. First run downloads several images, so give it a few minutes.

Check everything is healthy:

```powershell
docker compose ps
```

- HDFS NameNode UI: http://localhost:9870
- YARN ResourceManager UI: http://localhost:8088

## Step 1 — Dataset Collection and Understanding

```powershell
docker compose exec app python data/generate_dataset.py
docker compose exec app python data/explore_dataset.py
```

- `generate_dataset.py` simulates a Kaggle-style E-commerce transactions
  dataset (12 weeks, 8 categories, order/product/customer/return fields),
  since Kaggle requires a personal API token this box doesn't have. Two
  categories (`Footwear`, `Furniture`) are seeded with a rising return-rate
  trend on purpose so Step 5 has something real to detect. If you'd rather
  use a real Kaggle CSV, just drop it at `data/raw/transactions.csv` with
  the same columns and skip `generate_dataset.py`.
- `explore_dataset.py` prints dtypes + missing-value counts, imputes them,
  and writes `data/raw/transactions_clean.csv` (adds a `transaction_week`
  field used by every later step).

## Step 2 — Kafka-Based Data Streaming

In one terminal, start the consumer (it will wait for events):

```powershell
docker compose exec app python kafka/consumer.py
```

In a second terminal, run the producer:

```powershell
docker compose exec app python kafka/producer.py
```

The producer publishes every cleaned transaction row as a JSON event to
topic `transactions_events`. The consumer verifies receipt (prints a
sample + running counts) and buffers everything to
`data/streamed/transactions_stream.jsonl`.

## Step 3 — Hadoop HDFS Data Storage

```powershell
docker compose exec app python hdfs/store_to_hdfs.py
```

Creates `/data/transactions` in HDFS, uploads the buffered JSONL file, and
verifies it landed (size check + reads back the first line + directory
listing). You can also check it manually:

```powershell
docker exec namenode hdfs dfs -ls /data/transactions
docker exec namenode hdfs dfs -cat /data/transactions/transactions_stream.jsonl
```

## Step 4 — MapReduce Data Processing

Submitted from the `resourcemanager` container, which has the Hadoop
client + YARN config:

```powershell
docker exec -it resourcemanager bash /workspace/mapreduce/run_job.sh
```

- `mapper.py` emits `<category>|<week>  <quantity>  <returned_flag>` per
  transaction event.
- `reducer.py` sums quantity sold and quantity returned per
  category/week key.
- `run_job.sh` submits this as a Hadoop Streaming job reading from
  `/data/transactions/transactions_stream.jsonl` in HDFS, writes output to
  `/data/output/return_rate_mr` in HDFS, and also merges it down to
  `data/output/return_rate_mr.tsv` on the shared volume for Step 5.

Track progress in the YARN UI at http://localhost:8088.

## Step 5 — Return-Rate Calculation

```powershell
docker compose exec app python analysis/return_rate_analysis.py
```

- Computes `return_rate = total_returned / total_sold` per category/week.
- Prints overall return rate by category (highest first).
- Detects categories whose return rate is trending upward week over week.
- Flags every category/week combo (and every category overall) with a
  return rate greater than 10%.
- Writes the full detail table to `data/output/return_rate_report.csv`.

## Tearing down

```powershell
docker compose down -v
```

(`-v` also removes the HDFS namenode/datanode volumes so you get a clean
cluster next time.)
